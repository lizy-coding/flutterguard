## 保留、纠正与收缩

保留 ScanContext、SourceWorkspace 的共享读取/解析、CLI 命令族、单一规则注册表、
JSON/SARIF、抑制和 baseline。架构规则继续共用图与边界引擎，避免另建第二扫描器。
已有报告过滤在新规则 ID/证据设计确定后仍需回归验证，不能假定自动兼容。

IDE 保留 CLI 调用、超时/取消、文档快照、过期结果保护、错误提示与源码定位。
当前 Protocol 在第 30 行过滤其他文件，Annotator 第 69 行跳过无线号发现，
ScanAction 第 49 行汇报当前文件 findings；这些行为适合编辑器投影，不能扩展成
模块整体通过。先定义 CLI 的检查范围/覆盖信息，再决定最小项目结果入口。
不在插件内按目录或规则名称重新推断架构。

生命周期、BLE、凭据和状态框架专项不作为新首版的默认价值承诺。
先完成默认启用与兼容迁移方案，再移出默认集合或删除；本次未删除规则及其测试。
layer/module 规则暂保留共享执行实现，不再增加第三套边界逻辑。

旧 Timer、假凭据截图与说明不应继续担任新定位的主要示例。新演示需要覆盖：
入口访问合法、直接访问内部实现违规、同模块内部访问合法、合法入口重导出、
跨模块绕过入口重导出、未配置/归属冲突/无法解析的反馈。

## 建议执行顺序与验收

1. 先固定上述错误归属、export 漏检、重叠配置的反例，再纠正引用解析和归属。
   本包 package URI、相对 URI、export 和条件引用均需分别验证；外部包不能猜成本包。
2. 确定最小入口声明。外部引用先满足 allowed_deps，再满足目标入口要求；
   同模块内部引用合法，声明的入口可以重导出自身内部实现。
   首版不做符号级 API 泄漏或任意传递依赖的业务语义推导。
3. 统一配置语义验证与检查覆盖表达。具体字段/协议兼容方案尚待设计；
   不把未知状态塞入现有 severity/domain，也不随意修改退出码契约。
4. 同一份 CLI 结果驱动当前文件标注与必要的项目反馈；配置错误不能强行挂成某个
   import 的业务违规。模块配置或入口变化会影响未改动的调用者，不能只检查改动文件
   就宣称整体通过；先正确报告范围，再考虑有限增量优化。
5. 收缩默认规则、替换产品说明和示例，再做名称与发布材料迁移。

每步采用聚焦测试；CLI/检测器变更完成后执行根 AGENTS 的完整 Dart 门禁。
IDE 变更执行插件测试及实际场景验收。既有 10 月 10 日测试/截图不能作为新能力验收。
公开源码、原生平台矩阵、最终 Plugin Verifier、协议与账户事项仍是独立发布门禁。
