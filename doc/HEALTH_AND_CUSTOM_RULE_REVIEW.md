# BoundaryLens 健康评估与自定义规则诉求访谈

日期：2026-10-16。对象为 BoundaryLens 自身的工程与产品，不是被扫描项目的健康评分。
基点 ca80925 加未提交更名工作区。本轮只读审查源码并记录需求，没有重跑测试或改动检测实现。
72 项 Dart / 18 项 IDEA 是已有更名验证记录，不等于真实项目准确率或生产稳定性。

## 已确认的新增诉求

用户要求：在通用功能基础上，支持用户按特定要求自定义规则用于项目检测。
首轮已确认：跨业务的 Dart/Flutter 项目、有限声明式约束、规则随项目仓库维护。
不采用任意执行代码或规则市场方向；当前实现仍未提供这种自定义能力。
见 [方向决策](adr/0002-project-local-declarative-rules.md)。

后续用户已收敛首版：自定义规则暂缓，先交付内置检测与可验证的内部接入基础。
首版范围见 [ADR-0003](adr/0003-built-in-first-extensible-core.md)。本评估中的
自定义身份/分发等缺口不再全部转为首版待办，只处理当前内置检测实际需要的契约。

## 当前健康结论

| 维度 | 结论 | 当前证据与边界 |
|---|---|---|
| 扫描基础 | 可复用 | SourceWorkspace 共享源码/语法 AST/诊断；ScanContext 管理作用范围；无类型绑定/数据流事实 |
| 项目约束 | 有受控试用闭环 | 模块归属、依赖方向和公开入口；不能推断整体设计是否合理 |
| 执行与输出 | 可复用但需扩展契约 | 单一注册表、抑制、baseline、JSON/SARIF；图需求由内置规则硬编码 |
| 用户规则 | 尚未具备 | 只接受已注册 ID 和内置 options；没有外部规则加载或用户声明新检查的模型 |
| 可解释性 | 有欠账 | IDE 保留完整 findings，但 diagnostics 丢失结构、coverage reasons 未保留，报告尚无证据导航 |
| 范围可信度 | 有边界保护但未闭环 | 当前文件 stamp 保护有效；包扫描期间配置/其他文件变化没有对应快照保护 |
| 发布与复现 | 未就绪 | 更名未提交、默认243与本地261验证线不一致、新UI待人工验收、跨平台与Verifier待完成 |

不生成综合健康分。结论是可以在现有内核上继续试点，不是已经具备通用规则平台。

## 与新诉求最相关的技术缺口

1. RuleDefinition 有元数据和默认项，但没有独立参数类型/结构 schema。
   config_tools 从 defaultOptions 推导允许键，并拒绝未知 rule ID。
2. executor 接收完整上下文及可空图，输入需求/禁用/增量范围依赖内置实现自律；
   新检查不能直接假设符号解析、全项目图或完整执行路径已经存在。
3. coverage 目前只有 moduleBoundary，且任意 workspace 诊断都令其 partial。
   它不能直接代表多类用户规则各自的执行、跳过和证据不足。
4. 若允许用户命名规则，需要明确 ID 冲突、规则变更如何影响抑制与 baseline。
   当前静态目录不等于已建立自定义规则的身份与演进契约。
5. ImportGraph 为本地模块图，排除外部 package 引用。诸如“只有 data 层可以 import dio”
   的声明式约束还需要保留外部引用事实，不能假称现有 allowed_deps 已经覆盖。

代码入口：lib/src/rules/rule.dart、registry.dart、config_loader.dart、config_tools.dart、
scanner.dart、import_graph.dart，以及 IDEA 的 BoundaryLensProtocol/ScanAction。

## 官方能力与产品取舍

[Dart 官方 analyzer plugins](https://dart.dev/tools/analyzer-plugins) 已支持
自定义诊断、lint 与 IDE quick fixes。若目标只是让用户编写任意 Dart 分析规则，
必须先评估直接复用官方机制，不能将另造一个加载器本身视为产品差异。

首轮曾比较三个层次（用户已选择第二层）：

- 内置规则参数化：现有能力，可调整范围、启停与规则选项。
- 有限声明式约束：用户借助产品支持的事实/检查器表达自己的项目规则，不写执行代码。
- 可执行规则扩展：用户编写 Dart/脚本算法；涉及依赖、版本、隔离、权限与官方机制取舍。

当前 AGENTS 明确 CLI 没有扩展插件系统，现有规则词汇也是内置 detector。
只有最后一种方案获明确选择后，才讨论修改该边界；本轮不创建动态规则系统。
