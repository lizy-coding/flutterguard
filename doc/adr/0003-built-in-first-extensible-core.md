# 首版交付内置检测与可验证的内部扩展基础

状态：范围已接受，内部接入基础已实现并通过本地契约验收（2026-10-16）。

BoundaryLens 首版提供不同业务 Dart/Flutter 项目可用的内置模块检测，不开放用户自定义
规则。扩展性通过统一规则接入、事实需求、参数校验、执行结果和报告契约实现，
以现有能力范围内新增一条内置规则的接入测试证明，而不先创建 DSL、外部 SDK、
动态加载器、规则包或规则市场。

相比直接建设声明式规则平台，这保留了日后扩展的条件，同时优先完成现有模块检测
的解释、范围可信度和 IDE 使用闭环。ADR-0002 是长期候选方向，首版不实施。
CLI 继续拥有规则与事实，IDE 仍是结果适配器；不增加第二注册表或消费者业务耦合。

落实：RuleDefinition 声明输入、范围、激活条件及独立参数类型；RuleRunner 统一
准备共享事实、校验参数、跳过禁用规则并记录每条规则的执行覆盖。唯一产品注册表
仍是 RuleRegistry。内部临时测试规则证明接入、禁用、事实不足和 JSON 输出，
不加入产品目录。IDE 保留 coverage.rules 及原因，不增加 detector 或规则目录。

83 项 Dart 和 21 项 IDEA 测试通过，只证明本地实现契约。源码冻结、多平台产物、
新 UI 人工验收及公开合规材料仍是独立发布门禁，不由本 ADR 放行。
