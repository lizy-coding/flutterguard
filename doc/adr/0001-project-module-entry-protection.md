# 以项目声明的模块公开入口保护作为首个产品场景

状态：已接受（2026-10-16）；实现尚未完成。

FlutterGuard 的下一阶段以项目声明的模块路径、公开入口与允许依赖关系为输入，
检查外部模块是否绕过入口访问内部实现。首版继续限定 Dart 项目，复用 CLI 检测与
IDE 展示链路；消费者无需逐类声明职责，也无需引入运行时框架。

这一决定替代访谈期间讨论的 IoT 设备会话专项方向。自动推断业务状态机需要项目中
未必存在的语义与统一实现约定，容易令接入成本超过检测收益。项目架构约束则能够
由用户明确表达，并用源码引用提供可复核证据。

不以通用 lint 数量、综合健康评分或多语言支持作为首版目标。现有检测器是否删除、
配置与报告协议如何迁移、更名及发布身份另行处理；本决定不授权推送或发布。
